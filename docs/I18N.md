# Interface languages

FuelLog supports English (`en`, locale `en-GB`) and European Portuguese (`pt`,
locale `pt-PT`). Without a saved app choice, FuelLog uses the first supported
device language, falling back to English. The flag button in the top-right header,
next to feedback, opens a list with each language's name. It remains available
on every route, including when feedback is hidden.

The IndexedDB `settings.language` value is independent of `settings.priceCountry`.
Changing language does not change the station provider, country, currency, units,
receipt OCR model or imported data. Prices uses its own country flag selector.
Dates and displayed numbers use the selected language's locale; fill-up date entry
keeps the explicit `yyyy/mm/dd hh:mm` format and numeric inputs keep their existing
parsing rules. English and Portuguese catalogues are bundled and cached offline.

## Translation files

- `js/i18n/i18n.js`: registry, language selection, lookup, interpolation, locale and
  internal diagnostic translation. Browser helpers are `tr(key, values)` and `uiLocale()`.
- `js/i18n/en.js`: English source catalogue and registration metadata.
- `js/i18n/pt.js`: Portuguese catalogue with the same keys and placeholders.
- `js/ui-icons.js`: small inline SVGs for search, nearby search, edit and expansion.
  Icons have no language-dependent text or external font dependency.

Use stable keys such as `station.find` and named placeholders such as
`tr('language.current', {language: 'Português'})`. Missing entries fall back to
English; an unknown key is returned visibly so omissions can be found. Escape
translated strings when inserting them into HTML, just as with other text.

`FuelLogI18n.message` translates known internal diagnostic messages, including
parameterized calculation/import warnings, at presentation time. Data modules
retain their original diagnostics. Unknown browser, network and external error
messages can still appear in their original language. Never pass user-entered
vehicle/station names, notes, receipt product text or other imported content to
this helper. Fuel presentation translates canonical catalogue labels while
retaining unmatched source labels. Stored canonical fuel names and CSV headers
and fuel labels remain stable; JSON backups retain whole original records.

## Switching language safely

`refresh` loads the saved choice and applies `FuelLogI18n.resolve` before rendering.
A saved choice wins. If the setting is missing, empty or null, the resolver checks
`navigator.languages` in preference order, using `navigator.language` when the
list is absent or empty. It matches registered codes/locales first, then their
base language (for example `pt-BR` uses the Portuguese `pt` catalogue). Unsupported
device preferences fall back to English. Automatic detection is not written to
IndexedDB, so it follows the device on later launches until a choice is made.
Every explicit menu selection is saved, including the already displayed language,
and subsequent device-language changes cannot override it. Static
header/navigation nodes use explicit `data-i18n` attributes. Dynamic UI calls
`tr` when it renders, including deferred charts. Language changes capture and
restore unsaved fill-up, vehicle and promo controls before wiring their handlers.
The original urban-driving fraction and its edit state are preserved. History
filters and station-search controls/results are also retained. A replaced Leaflet
map is disposed before rebuilding it. No log records are rewritten by selection.

A full JSON backup includes the language setting without changing backup version
4 or the IndexedDB schema. Merge retains local settings; replacement restores the
backed-up language and country independently. Replacement upserts settings rather
than clearing the settings store: a backup
without a language key retains any existing local choice. If neither backup nor
local storage supplies a choice, FuelLog uses the device-language default.
Unsupported saved language codes still fall back to English.

## Adding a language

1. Copy `en.js` to a new file in `js/i18n/` and translate all values, keeping keys
   and named placeholders unchanged.
2. Register a unique code, native language name, locale and flag in that file.
   Flags are accompanied by language names in the chooser and accessible labels.
3. Include the file in `index.html` after the registry and English catalogue.
   The chooser is populated from the registrations automatically.
4. Add it to `sw.js` `ASSETS`; update all release markers and runtime URL queries
   together as described in [UPDATES.md](UPDATES.md).
5. Extend `scripts/check-i18n.js` to load and compare its catalogue, and verify
   long labels, locale formatting and offline switching in the browser.

## Verification

`node scripts/check-i18n.js` checks matching keys/placeholders, English fallback,
parameterized diagnostics, literal references, locale formatting, translated
views, unmodified user data and canonical CSV fuel labels. Backup checks cover
language/country preservation. `check-device-language.js` checks preference order,
regional variants, older-browser language fallback, an unchanged explicit choice
and independence from station country. CI runs these with the regression suite.

`node scripts/browser-i18n.cjs` uses an isolated Chromium context with synthetic
records. It checks 375/320px layouts, flag accessibility and persistence, independent
country selection, unsaved forms, History filters, reference prices, chart labels
and offline reload/switching. It also checks Portuguese device defaults, unsupported
language fallback, changing device preferences, and persistence of an explicit
selection of the currently displayed language. It accepts the same `FUELLOG_QA_URL`,
`FUELLOG_QA_PLAYWRIGHT` and `FUELLOG_QA_CHROMIUM` overrides as other browser checks.
This is not proof of Safari 12 or physical iPhone 6/Home Screen compatibility.
